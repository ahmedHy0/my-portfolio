# Phase 04 — Core Layout and Responsive Structure

## Objective

Implement the static, semantic, responsive portfolio structure before adding complex motion.

## Build Order

1. App shell and global background.
2. Header and navigation.
3. Intro shell.
4. Hero.
5. About.
6. Skills/Data Stack.
7. Background/Education/Training.
8. Certifications.
9. Projects.
10. Contact/Open to Opportunities.
11. Footer.

## Requirements

- Use semantic landmarks.
- Maintain one meaningful `h1`.
- Keep content readable without JavaScript animation.
- Keep all real links functional.
- Use the provided logo, portrait, CV, and project images.
- Do not show internal file names or source notes.
- Do not create fake dashboards or metrics.

## Responsive Behavior

Test during implementation at:

```text
320px, 375px, 390px, 414px, 768px, 1024px, 1280px, 1440px
```

Mobile must be a deliberate one-column composition, not a compressed desktop layout. Convert dense diagrams, timelines, and skill maps to readable cards or accordions where necessary.

## Deliverable Before Phase 05

The entire page must be navigable and readable with minimal styling and no advanced animation. Confirm there is no horizontal overflow, clipped text, broken image, or dead link.

Run the available development, lint, and build checks before moving on.
