# Phase 06 — Project Case Studies and Pipeline Visualizations

## Objective

Turn the three provided projects into credible, visually strong Data Engineering case studies.

## Required Case Study Structure

For each project, show:

1. Real project name.
2. Category based on source material.
3. Concise problem/purpose.
4. Data input or source if documented.
5. Pipeline stages if documented.
6. Transformations or processing.
7. Storage/output if documented.
8. Technologies.
9. Screenshot or preview from the project folder.
10. Real source/demo link.
11. Honest project status.

Use the actual architecture rather than forcing every project into the same diagram.

## Pipeline Visuals

When supported, show:

```text
SOURCE → VALIDATE → TRANSFORM → STORE → SERVE
```

or the actual project flow.

Animate lightweight SVG/CSS data packets. Provide a visible static text equivalent. Label any interactive replay as sample data.

## Case Detail Interaction

The modal/drawer/route must:

- Have an accessible name.
- Trap focus.
- Close with button and Escape.
- Restore focus.
- Prevent background scroll only while open.
- Work on touch screens.
- Avoid double scrollbars.

## Honesty

Never turn a screenshot into a live demo. Never invent rows, latency, users, volume, uptime, cloud deployment, or production use. Use `Project preview` rather than `No live demo exists`.

## Deliverable Before Phase 07

Open and inspect all three case studies on desktop and mobile. Verify titles, descriptions, images, technologies, and links against the source files. Fix any mismatch before proceeding.
